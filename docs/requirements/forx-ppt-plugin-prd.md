# forx PPT 对话创作插件：产品需求文档

版本：v0.1 · 评审草案  
日期：2026-10-23  
适用项目：`D:\hermes-forx`  
插件暂定标识：`forx-ppt`，正式名称可调整。

本文用于产品评审、设计和研发拆解，不代表功能已经实现。用户已确认首版采用“插件内实时预览，导出可编辑 PPTX”；其余优先级、容量和性能数值为本次整理提出的建议基线，开发前需评审。

## 1. 产品定位与目标

在 forx 中提供一个通过自然语言持续制作和修改 PPT 的插件。用户可以生成演示文稿，在预览中查看页面与元素编号，通过对话修改指定对象、母版公共元素和整份文稿的主题，最后导出能够继续编辑的 `.pptx` 文件。

产品的核心不是一次性生成文件，而是让同一份演示文稿在多轮对话中持续、准确地演进。

| 用户原始需求 | 产品能力 | 核心验收结果 |
| --- | --- | --- |
| 生成可以编辑的 PPT 文件 | 原生 PPTX 生成与导出 | 文本、形状、表格、基础图表保持各自的编辑能力 |
| 每页元素编号命名 | 稳定标识、语义名称、编号显示与元素列表 | 每个可寻址对象都能被查找，页面重排不导致引用错位 |
| 按母版元素统一实时对话编辑 | 母版、版式和继承关系管理 | 一次修改更新所有继承对象，新页面继续继承 |
| 按某页某元素编号针对性编辑 | 页面与元素精确定位、局部修改 | 指令只修改指定目标，其他对象保持不变 |
| 实时对话修改主题风格 | 全局主题与样式联动 | 颜色、字体和预设风格同步更新，内容及局部定制按规则保留 |

## 2. 已确认范围与产品边界

### 2.1 首版交付形态

- 面向 forx 桌面端提供插件工作区，与聊天协同使用。
- 在插件中生成、选择、预览和对话编辑 PPT；编辑完成后无需手动刷新预览。
- 支持保存可继续编辑的插件项目，随时导出当前已保存版本的 `.pptx`。
- 以插件自建文稿、内置母版和自身导出的 PPTX 为首版可靠支持范围。
- 首版覆盖全部五项核心能力，不能以“仅生成 PPT 文件”作为完整首版交付。

### 2.2 “实时”的明确含义

“实时对话编辑”指：用户发送指令后，系统显示处理状态，执行修改，自动更新插件中的当前页面和相关缩略图，并反馈修改对象与影响范围。它不要求每输入一个字就触发修改。

首版的实时效果发生在插件内。PowerPoint/WPS 可以在导出后打开文件继续编辑；与已打开的 Office/WPS 窗口进行双向实时同步属于后续独立能力。

### 2.3 首版范围之外

- 任意历史 PPTX 的完整无损导入与任意复杂母版兼容。
- 旧版 `.ppt`、带宏 `.pptm`、加密演示文稿的编辑。
- 多人同时编辑与冲突自动合并。
- 复杂动画、转场、SmartArt、嵌入式 OLE 和音视频对象的完整编辑。
- 将整页截图或 PDF 自动还原为全部可编辑原生对象。
- 必须依赖新增图片生成服务才能完成的风格改造。

上述内容不影响首版对原生文本、形状、图片、表格和基础图表的支持。

## 3. 目标用户与典型任务

| 用户 | 典型任务 | 主要诉求 |
| --- | --- | --- |
| 商务、销售、运营人员 | 方案介绍、客户提案、业务汇报 | 快速生成，反复改文案，统一品牌 |
| 产品和项目负责人 | 产品介绍、项目评审、阶段汇报 | 按页面与对象精确修改，不影响其他内容 |
| 教师、培训及内容创作者 | 课程、培训、分享材料 | 调整结构和风格，多轮持续编辑 |
| 企业模板维护人员 | 管理 Logo、标题、页脚和版式 | 修改母版后统一联动，保留合理例外 |

典型任务示例：

1. “生成一份 12 页的产品发布会 PPT，面向企业客户，采用简洁商务风。”
2. “把母版中的 Logo 换成这个图片，统一放到右上角。”
3. “把第 5 页的 E0017 标题改成‘增长来自产品升级’，字号调大两号。”
4. “把整份 PPT 改成深色科技风，保留现有文案和图表数据。”
5. “撤销刚才的主题变化，只保留标题修改。”

## 4. 核心概念与对象规则

### 4.1 文稿、母版、版式、页面、元素与主题

| 概念 | 定义 | 示例 |
| --- | --- | --- |
| 文稿 / 项目 | 一个可持续编辑的作品，含页面、素材、主题、版本及修改记录 | 产品发布会方案 |
| 母版 | 定义一组页面共享的公共对象和基础样式 | Logo、页脚、背景装饰、基础字体 |
| 版式 | 定义某类页面的占位符、位置和样式 | 封面、目录、标题正文、左右图文、结束页 |
| 页面 | 实际幻灯片，引用母版与版式，保存本页内容和局部设置 | 第 5 页“市场机会” |
| 元素 | 可独立选择和定位的对象 | 标题框、图片、形状、表格、图表、组合 |
| 主题 | 文稿使用的语义颜色、字体和风格参数集合 | 主色、强调色、正文色、字体、线条和圆角规则 |

母版公共对象、版式占位符和页面独立对象需要在界面中明确区分。不能因为它们在一页里看起来相同，就当作没有关联的独立副本。

PPT 主题控制文稿的样式；插件界面的明暗主题沿用 forx 自身设置，二者独立。

### 4.2 稳定编号与语义名称

编号分为“身份编号”和“当前顺序”。当前第几页可以变化，页面和元素的身份编号保持稳定。

| 对象 | 编号示例 | 规则 |
| --- | --- | --- |
| 文稿 | 内部唯一 `deck_id` | 用于隔离不同作品；不同文稿可出现相同可读短编号 |
| 页面 | `S003` | 文稿内唯一，创建后不因插入、删除或重排而改变 |
| 元素 | `E0017` | 文稿内唯一，跨页面、母版及版式统一分配，不因改名或移动而改变 |
| 母版 | `M001` | 文稿内唯一，可按编号进入母版编辑 |
| 版式 | `L002` | 文稿内唯一，与所属母版和引用页面关联 |

用户看到的对象标签示例：`第 5 页 · S003 · E0017 · 营收趋势图`。其中“第 5 页”表示当前顺序，`S003` 和 `E0017` 表示稳定身份。

必须遵守以下规则：

1. 为每个可寻址原生对象分配编号与名称，包括装饰形状、组合及其子对象；整页背景色等页面属性通过页面编号定位。
2. 支持自动命名与手动改名，例如“主标题”“产品示意图”“营收趋势图”。名称可以重复，编号不能重复。
3. 删除后不复用旧编号；撤销删除恢复原身份；复制对象或页面分配新的身份编号。
4. 元素移到另一页时保留元素编号，更新所在页面；页面前缀与实际归属不符时必须指出冲突，不能误改。
5. 同一母版公共元素在多个页面中出现，仍指向同一个源编号；页面上的显示是继承呈现，不创建多个独立身份。
6. 组合有自身编号，子对象保留各自编号；表格单元格、图表系列通过所属对象下的子位置定位。
7. 用户按“第 3 页”发出指令时，以提交时的页面顺序解析，并在执行前绑定稳定编号与文稿版本。

### 4.3 支持的定位方式

| 方式 | 示例 | 处理规则 |
| --- | --- | --- |
| 按稳定元素编号 | “把 E0017 改成蓝色” | 在当前文稿中精确定位 |
| 页面加元素编号 | “修改 S003 的 E0017” | 同时校验页面归属 |
| 当前页码加编号 | “第 5 页的 E0017 往右移动” | 先把当前页码解析为稳定页面身份 |
| 按名称 | “把第 5 页的主标题加粗” | 唯一时执行，重名时展示候选对象 |
| 按界面选择 | “把选中的图表放大” | 使用消息提交时已选中的对象快照 |
| 按母版来源 | “修改 M001 中的 E0002 Logo” | 按母版范围执行并显示影响页数 |
| 按子位置 | “将 E0021 表格第 2 行第 3 列改为 80%” | 对父对象和子位置共同校验 |

## 5. 功能需求

优先级定义：**P0** 为完整首版必需；**P1** 为后续增强；**P2** 为远期探索。未标明例外的本节要求均为 P0。

### FR-01：创建演示文稿与生成内容

**输入：**主题、用途、受众、语言、页数或页数范围、已有文案、素材和风格偏好。

**要求：**

- 支持从空白开始，也支持基于内置母版和版式创建。
- 默认采用 16:9，可在创建时选择其他已支持比例；生成后的比例变更需按整体重排处理。
- 支持先生成大纲再生成页面，也支持用户直接要求生成完整初稿。
- 内容应覆盖标题、正文、列表和按需生成的形状、图片、表格、基础图表。
- 新增、复制、删除、重排页面，以及基于当前主题新增页面，均需保留正确的身份和继承关系。
- 缺少业务数据时使用明确占位或询问用户；不能把虚构数字包装成用户提供的事实。

**验收：**按约定页数生成初稿，页面可预览，所有可寻址对象具有编号；新插入页面沿用当前母版和主题。

### FR-02：可编辑 PPTX 与可恢复项目

**要求：**

- 导出标准 `.pptx`；文本是文本框，形状是原生形状，表格是原生表格。
- 基础图表至少支持柱状图、折线图和饼图，以原生图表及其可编辑数据导出。
- 图片保持独立图片对象，可以移动、缩放、裁剪、替换；不承诺图片内部像素或图片中的文字可像文本框一样编辑。
- 内容中的文本与装饰背景尽量分离，不得将整页内容栅格化后作为“可编辑 PPT”交付。
- 将共享母版对象、版式、占位符和主题映射到 PPTX 对应结构，不能只逐页复制对象来模拟统一母版。
- 支持保存包含结构、素材、绑定关系与修改记录的插件项目；重新打开项目后可以继续对话编辑。
- 自身导出的 PPTX 再导入时，在元数据完整且未经外部改写的支持范围内，恢复编号、原生结构和样式绑定。外部软件改写后的通用兼容属于 P1。
- PPTX 不要求携带完整对话历史；项目文件承担完整会话修改记录的恢复。
- 导出对象名称包含编号和语义名称，例如 `E0017_营收趋势图`，便于在外部软件的对象选择列表中识别。
- 编号、来源和绑定关系需有持久化元数据；不能只依赖易变化的对象名称或数组下标。
- 导出绑定一个已提交版本，导出期间后续编辑不会混入同一个文件；界面显示导出版本与时间。

**验收：**在发布时声明支持的 PowerPoint/WPS 版本中打开，编辑并保存文本、图片、形状、表格和图表数据；导出文件不要求修复，主母版和版式能在母版视图中识别。

### FR-03：元素编号、命名与查找

**要求：**

- 提供“显示 / 隐藏编号”开关；编号默认作为编辑辅助层，不出现在正式导出的页面画面中。
- 页面旁提供元素列表，展示编号、名称、类型、所属页面或母版、可见状态和样式来源。
- 点击画布对象高亮对应列表项；点击列表项定位并高亮画布对象。
- 支持搜索编号和名称，支持一键将对象引用带入对话输入框。
- 遮挡对象、隐藏对象、组合子对象和母版继承对象都能从列表定位。
- 母版继承对象需标记“来自 M001 / L002”；页面局部样式需标记“本页覆盖”。

**验收：**在存在重名、组合和重叠对象的页面中，用户仍可定位指定编号；重命名和页面重排后原编号仍有效。

### FR-04：按页面与元素实时对话编辑

**支持的操作：**

| 对象 | 首版编辑能力 |
| --- | --- |
| 文本框 / 占位符 | 修改文案、字体、字号、颜色、字重、段落、对齐和文本框尺寸 |
| 形状 | 调整位置、尺寸、填充、边框、圆角等已支持属性 |
| 图片 | 替换图片、移动、缩放、裁剪，默认保持原对象身份 |
| 表格 | 修改单元格内容、增删行列、调整列宽和已支持的表格样式 |
| 图表 | 修改标题、分类、系列、数据、颜色和尺寸 |
| 组合 / 多选对象 | 整体移动、缩放、对齐、分布，或明确选定子对象修改 |
| 页面 | 调整顺序、背景、版式，以及新增和删除页面 |

**执行规则：**

1. 一条指令可以包含多个修改，例如“E0017 标题改短，E0018 图片缩小 20%”。
2. 相对指令必须有可解释的基准；“缩小 20%”默认相对当前尺寸；“放大一点”使用可见的默认步长，必要时提供数值选项。
3. 只改被指定的属性。修改标题文案不应重建整页，也不应重新分配其他对象编号。
4. 修改完成后自动更新预览，反馈目标编号与修改摘要；支持查看修改前后效果。
5. 支持“继续把它加粗”等跟进指令。所指对象必须来自当前文稿中已确定的最近目标或显式选择，不能跨文稿沿用。
6. 标题与正文占位符的文字属于页面内容；母版统一字号不意味着把每页标题文案改成相同内容。

**验收：**“把第 5 页 E0017 的标题改成‘新市场机会’并设为 32 磅”只改变目标文本及字号，其他页面、对象及图表数据保持不变。

### FR-05：母版与版式的统一实时编辑

**首版母版范围：**每份文稿支持一套主母版，至少提供封面、目录、标题正文、图文和结束页版式；多套独立母版管理为 P1。

**要求：**

- 提供母版与版式编辑入口，展示公共元素、样式、继承页面与例外数量。
- 支持通过母版 / 版式编号和元素编号修改 Logo、页脚、背景装饰、标题与正文样式、占位区域及其他已支持对象。
- 支持作用域：整套母版、某个版式、当前页面、明确指定的页面集合；操作是否合法取决于目标属性的来源。
- 编辑母版源对象前先展示影响范围，明确哪些页面继承、哪些属性存在局部覆盖；范围明确时按指令执行，无需每次重复确认。
- 母版修改后，所有继承对应属性的页面自动更新；以后新建的页面也必须继承新值。
- 编辑版式只影响使用该版式并继续继承对应属性的页面。
- “只改本页”对于页面自身对象和页面占位符产生局部覆盖；不得反向污染母版。
- 对于直接继承的母版公共对象，单页显示引用不能冒充独立页面对象。若首版没有可安全表达的原生单页例外方式，应保留原稿并提示用户选择修改母版或更换版式；不能偷偷扩大到所有页面，也不能用背景色遮盖原对象。
- 母版公共对象的完整单页局部变体管理作为 P1，具体能力在技术验证后进入范围评审。
- 支持查看和清除某个属性的局部覆盖，恢复继承；除非用户明确要求，不清除其他属性或页面内容。

**验收：**修改母版 Logo 后，所有引用页面和随后新增页面更新；修改标题默认字号后，未覆盖字号的页面更新，已覆盖字号的页面保留并列入例外清单。

### FR-06：主题与风格实时对话修改

**要求：**

- 首版提供至少三套完整主题预设，并支持通过对话调整主色、辅助色、字体、背景和已支持的风格参数。
- 至少覆盖商务简洁、深色科技、清新极简三类方向；实际预设名称和视觉方案由设计评审确定。
- 主题使用语义化颜色和字体角色，例如“标题色”“正文色”“强调色”“标题字体”，绑定这些角色的对象自动联动。
- “改成深色科技风”应同时处理背景、可读文本色、字体层级、图表配色和预设中的形状 / 装饰风格，不应仅更换背景色。
- 默认只更新绑定主题或母版的样式，保留用户明确设置的局部样式，并展示保留项。
- 用户明确说“包括局部覆盖一起统一”时，展示被覆盖的例外范围，并只统一此次点名的样式属性。
- 默认保留页面顺序、文案、表格和图表数据、对象身份；不自动重写内容或替换图片素材。
- 如果风格要求涉及布局重排，先提供重排预览，再应用整组变更；普通换色和换字体不能无提示触发内容重组。
- 主题更换后进行溢出、遮挡和基础可读性检查；检查失败时显示问题页面，不得把尚有问题的结果标记为验证通过。
- 风格属于整份文稿；“只改第 3 页风格”按页面局部样式处理，提示其成为例外，不改变全局主题。
- 支持撤销主题修改、恢复之前的主题与覆盖关系。

**验收：**从浅色主题切换深色主题，标题、正文、背景与基础图表联动；内容和数据相同，编号相同；局部定制按明确策略保留或更新。

### FR-07：对话上下文、歧义与作用域

**要求：**

- 每条指令绑定当前文稿、提交时版本、选中对象、页面身份和编辑范围。
- 指定唯一目标且范围清楚的修改直接执行；编号不存在、对象归属冲突、名称重名或指代不明时，展示候选并请求补充。
- 不能因为“改一下标题”不明确，就默认修改全篇所有标题。
- 消息携带的目标引用需可点击回到对象，便于用户核对。
- 跨文稿切换后清除不适用的代词指向和选中状态；恢复旧文稿时恢复其自己的状态。
- 相互依赖的修改按顺序执行；早先请求的迟到结果不能覆盖后来的已提交修改。
- 首版同一文稿串行提交修改；版本已过期时重新核对目标与差异，不盲目覆盖。

**验收：**连续提交两条标题修改，最终结果对应有效的后续指令；旧结果迟到、页面重排或切换文稿都不会把修改写到其他对象。

### FR-08：版本、撤销与修改记录

**要求：**

- 每次已成功提交的对话修改形成一个可追溯版本；一条包含多个对象的指令默认作为一个操作组。
- 支持撤销、重做，以及恢复已保存的历史版本；恢复也形成新的当前版本。
- 记录用户指令、影响范围、目标编号、关键属性变化和执行结果，方便回看。
- 预览中的待处理修改和已保存版本明确区分；只有完整校验并提交的版本才可导出。
- 一组修改执行失败时整体保留原版本，不能一部分页面已变化、另一部分没有变化却显示成功。
- 支持自动保存和重新打开恢复；恢复项目不依赖聊天模型仍保有完整历史上下文。

**验收：**对全篇进行母版修改、主题修改和指定元素修改后，逐步撤销与重做，视觉、数据、编号及继承关系均能恢复。

### FR-09：预览、选择与问题提示

**要求：**

- 提供页面缩略图、当前页预览、元素列表、编号显示、缩放和选择高亮。
- 当前预览、元素列表、母版关系和导出文件来自同一个文稿版本，不能各自维护一套互不一致的状态。
- 修改页面优先更新当前可见预览；后台更新其他受影响缩略图，并显示整体完成情况。
- 导出前检查内容溢出、对象越界、缺失素材、缺失字体和基础可读性问题。
- 预览可由渲染结果呈现，但导出必须保持对象结构；采用图像预览时，点击选择仍需有可靠的对象位置映射。
- 字体或渲染环境造成外部软件中的差异应能被检测并给出替代方案；不承诺不同软件间像素级完全一致。

**验收：**点击预览中的某个图表，定位到正确编号；修改后无需刷新，当前页与缩略图更新，导出的同版本结果与预览保持已声明的兼容程度。

### FR-10：项目、素材与导出管理

**要求：**

- 支持项目新建、命名、保存、重新打开和复制。
- 图片等素材随项目管理，避免原始文件移动后项目静默失效。
- 支持上传替换图片，显示素材加载失败原因及修复入口。
- 导出失败保留当前文稿和编辑记录，提供重试或另存位置。
- 对插件项目之外的外部文件修改，采用显式重新导入流程；首版不监听 Office/WPS 并自动合并。

**验收：**关闭并重新打开插件后，文稿、素材、编号、母版和主题仍可继续编辑；某张图片失效不会导致整份项目不可打开。

## 6. 样式继承与覆盖规则

本节是母版联动与主题修改的统一行为合同，所有编辑入口必须使用相同规则。

### 6.1 属性级继承

对可继承的属性逐项解析，而不是给整个对象设置一个粗粒度“脱离母版”标志：

`本页显式覆盖 > 版式设定 > 母版设定 > 主题默认值`

母版、版式和页面属性都可引用主题角色；主题切换只更新仍存在引用关系的值。上述规则是产品模型，导出时需要映射为 PPTX 能表达的原生主题和继承结构。

例如：某标题单独设为红色，但字号仍继承母版。以后统一修改母版字号时，该标题跟随更新字号，同时保留红色。

### 6.2 默认策略

| 指令 | 默认行为 |
| --- | --- |
| “母版标题字号改成 32 磅” | 更新继承此字号的页面，保留本页字号覆盖 |
| “第 5 页标题改成红色” | 只建立该页对应标题的颜色覆盖 |
| “恢复第 5 页标题颜色跟随母版” | 只清除颜色覆盖，保留文字和其他覆盖 |
| “全篇换成深色科技风” | 更新主题绑定和预设样式，列出仍保留的局部例外 |
| “所有标题颜色统一为白色，包括局部设置” | 显示范围后统一标题颜色，不清除无关字号或布局设置 |
| “把母版标题样式统一” | 更新样式，保留各页不同的标题文字 |

布局、位置与公共图形的继承并不等同于字体颜色继承。对无法用当前支持的原生结构安全表达的操作，按 FR-05 提示范围或能力限制，不能伪造已完成结果。

## 7. 主要交互流程

### 7.1 新建并持续修改

1. 用户打开 PPT 插件，输入主题、受众、页数和风格；缺失信息使用可见默认值。
2. 系统生成大纲；用户可确认大纲，也可明确跳过直接生成初稿。
3. 系统生成页面、稳定编号、母版和主题，并显示可编辑预览。
4. 用户点击对象或输入编号，通过对话修改文案、图片、数据和样式。
5. 系统自动保存成功版本，用户可以撤销、继续修改或导出 PPTX。

### 7.2 统一修改母版

1. 用户打开母版面板，或说“把母版 Logo 换成这个图片”。
2. 系统定位源对象，显示来源编号、继承页数与例外。
3. 指令范围明确时执行；范围存在歧义时让用户选择。
4. 校验后提交一个版本，更新受影响页面，并反馈实际更新与保留数量。
5. 用户可查看例外、恢复继承，或整体撤销本次修改。

### 7.3 按编号精确修改

1. 用户打开编号显示或从元素列表选择对象。
2. 对话输入框带入 `S003 / E0017` 引用。
3. 用户说“标题缩短为 12 字以内，保持位置和字号”。
4. 系统只修改该对象文案并检查溢出；不能自动调整未获授权的布局。
5. 预览和修改摘要展示该对象的结果，其他对象保持不变。

### 7.4 切换主题风格

1. 用户说“换成深色科技风，保留现有内容”。
2. 系统展示主题效果、作用范围和局部样式保留情况。
3. 普通主题参数变更执行并形成可撤销版本；需要重排时先展示重排方案。
4. 更新预览并检查问题页面，允许继续微调、撤销或导出。

### 7.5 处理状态

界面至少区分：空白、生成中、解析指令中、等待明确目标、应用中、更新预览中、已保存、失败、连接中断、导出中。

“模型已生成回复”“命令已执行”“预览已更新”“文件已保存”是不同状态，不能提前展示统一的“已完成”。

## 8. 界面与信息布局

| 区域 | 内容 |
| --- | --- |
| 聊天区 | 自然语言输入、对象引用、处理状态、修改摘要、澄清选项 |
| 页面导航区 | 缩略图、当前页码、稳定页面编号、页面重排和问题标记 |
| 主预览区 | 页面、缩放、选择框、编号辅助层、修改前后切换 |
| 元素 / 属性区 | 编号、名称、类型、位置、样式来源、覆盖状态和查找 |
| 母版 / 主题区 | 母版、版式、继承范围、主题预设及主要风格参数 |
| 项目操作区 | 保存状态、撤销、重做、历史版本、导出 |

窗口较窄时支持面板折叠；复杂操作不强制把所有控件同时展开。精确数值输入用于辅助修改，对话始终是主要入口。

## 9. 数据与执行约束

此处定义产品必须具备的数据关系，不锁定实现库或具体接口。

| 实体 | 必需信息 |
| --- | --- |
| 文稿 | 身份、名称、页面顺序、当前版本、主题、母版集合、保存状态 |
| 页面 | 稳定编号、名称、母版和版式引用、对象集合、页面属性 |
| 元素 | 稳定身份与可读编号、名称、类型、父对象、内容、几何属性、样式、来源和覆盖关系 |
| 母版 / 版式 | 稳定编号、公共对象、占位符、样式与引用关系 |
| 主题 | 语义颜色、字体、风格参数及对象绑定关系 |
| 编辑操作 | 目标文稿、基准版本、作用域、目标编号、属性变化、状态、前后版本 |
| 素材 | 身份、内容或受控位置、类型、引用对象和可用状态 |

执行链要求：`解析意图 → 绑定目标与版本 → 校验范围及能力 → 应用操作组 → 验证结果 → 提交版本 → 更新预览与保存状态`。

模型负责理解用户意图和提出变更，文稿执行层负责校验目标、允许的属性和版本，并确定性地执行；不能依赖模型自由重写整份 PPT 来完成一个局部修改。

## 10. 非功能需求

### 10.1 正确性与可靠性

- 精确定位优先：系统无法确定目标时，保持原稿并澄清。
- 同一指令的重复提交应能识别，避免重试后重复新增页面或对象。
- 保存中断、渲染失败或导出失败不破坏最后一个成功版本；重新打开能恢复。
- 项目源数据、预览缓存与导出结果有明确版本关系，清理缓存不能丢失作品。
- 文稿和素材按连接、用户配置作用域、项目隔离；不能因切换配置或文稿而串写。

### 10.2 性能目标

以下为建议验收目标，尚未实测；实现评审需要固定硬件、模型、素材和渲染环境。

建议基准：Windows 11、4 核 CPU、16 GB 内存；30 页文稿，每页不超过 60 个可寻址对象，素材总量不超过 50 MB。

| 操作 | 建议目标 | 计时边界 |
| --- | --- | --- |
| 收到用户编辑指令后显示处理状态 | 1 秒内 | 从点击发送至显示已接收 / 处理中 |
| 点击对象并高亮 | p95 不超过 150 毫秒 | 预览已加载后，点击至高亮 |
| 单页常规属性修改更新预览 | p95 不超过 2 秒 | 结构化变更已生成后，至当前页正确更新 |
| 30 页母版 / 主题变更 | 当前页优先，全部受影响预览 p95 不超过 10 秒 | 结构化变更已生成后，至全部预览更新 |
| 自动保存 | 成功提交后 2 秒内完成 | 仅针对编辑版本持久化，不含完整 PPTX 导出 |
| 30 页 PPTX 导出 | p95 不超过 30 秒 | 点击导出至文件可用 |

模型推理和新增素材获取耗时单独记录，完整端到端耗时也需报告，不能只用执行耗时宣传“实时”。长操作提供持续状态与取消入口，不能无期限显示空白加载。

### 10.3 兼容性与数据使用

- 首版以 Windows 桌面环境作为优先验收平台；跨平台覆盖根据渲染链验证结果扩展。
- 发版前固定支持的 PowerPoint 和 WPS 具体版本，使用真实软件验证原生编辑、母版和字体行为。
- 核心文件生成与结构编辑不依赖用户打开 Office；预览所需渲染依赖通过安装与设置流程检测并提示。
- 文稿内容和素材按 forx 已配置的模型及服务路径处理；需要额外外部服务时提供明确配置和数据说明。
- 默认不新增遥测或素材外传渠道；凭据沿用宿主配置机制，行为设置进入配置文件和设置界面。

## 11. 异常与边界场景

| 场景 | 必须行为 |
| --- | --- |
| 编号不存在或目标已删除 | 提示未找到，提供搜索或撤销入口，不修改近似对象 |
| 名称重复、指代不清 | 展示带页码和编号的候选目标，等待用户选择 |
| 目标是母版继承对象 | 显示母版来源和影响范围，禁止当作普通局部对象处理 |
| 单页覆盖与母版统一冲突 | 保留覆盖并列为例外，除非用户明确要求统一该属性 |
| 文案超出文本框 | 提示问题，提供缩字、缩写、扩框或重排选项，不静默截断 |
| 字体缺失或图片损坏 | 定位对象并提供替换入口，保留其他已完成内容 |
| 模型返回不支持的修改 | 说明具体能力限制并保留原稿，不宣称操作成功 |
| 应用操作组时失败 | 不提交部分结果，恢复该组修改前版本 |
| 预览失败但编辑版本已保存 | 明示版本已保存、预览未更新，允许重试，禁止显示旧图为最新 |
| 同一文稿版本已变化 | 重新核对目标与变化，防止旧操作覆盖新结果 |
| 导出失败、无写权限或磁盘不足 | 保留项目，提供另存位置或重试 |
| 自身导出文件的标识元数据缺失 | 说明不能可靠恢复原编号；由用户选择作为新文稿导入，不冒用旧身份 |

## 12. 首版验收场景

本表是验收场景，不要求每行拆成一个重复的单元测试。自动化验证应围绕稳定身份、作用域、继承和版本等行为合同组织，并补充真实 PPTX、渲染链与外部软件验证。

| 编号 | 场景与操作 | 通过标准 |
| --- | --- | --- |
| AC-01 | 根据主题生成一份包含文本、形状、图片、表格与基础图表的文稿 | 页面数符合要求，可预览；对象有独立身份并可继续修改 |
| AC-02 | 导出并在声明支持的 PowerPoint/WPS 中编辑后保存 | 文本可改字，表格可改单元格，图表可改数据，图片可替换；文件无需修复 |
| AC-03 | 开启编号，对重名、组合及遮挡对象进行选择 | 画布与列表双向定位准确；辅助编号不出现在正式页面画面中 |
| AC-04 | 在原第 3 页之前插入页面，再按旧稳定元素编号修改 | 仍命中原对象；“当前第 3 页”与稳定页面身份在界面中可区分 |
| AC-05 | 复制页面、移动元素、删除并撤销 | 复制获得新身份；移动保留元素身份；撤销恢复原身份；无编号复用 |
| AC-06 | 只修改第 5 页 E0017 的文案和字号 | 只改变目标属性；其他对象、页面和数据不变 |
| AC-07 | 修改母版 Logo，并新增引用页面 | 所有引用页面及新页面更新，母版中存在可编辑源对象 |
| AC-08 | 单页标题覆盖颜色后，统一修改母版字号 | 字号更新、局部颜色保留；清除颜色覆盖后恢复继承 |
| AC-09 | 将全篇从浅色切成深色主题 | 绑定样式和图表配色联动；文本、数据、身份不变；例外可追溯 |
| AC-10 | 连续修改标题、主题和母版，再撤销 / 重做 | 每步恢复对应内容、样式、身份和继承关系；操作组完整 |
| AC-11 | 连续编辑，模拟迟到结果、重试和切换文稿 | 旧结果不覆盖新版本；重试不重复新增；其他文稿不受影响 |
| AC-12 | 保存项目并重开，自身导出 PPTX 再导入 | 项目恢复完整状态；支持范围内的 PPTX 恢复身份及主题 / 母版绑定 |
| AC-13 | 模拟渲染、素材和导出失败 | 错误可定位、可恢复，最后成功版本保留，无虚假“已完成” |

发版门槛：五项核心需求及相关 P0 场景通过；存在对象变截图、精确指令误改其他对象、全局修改丢失局部设置或失败破坏原稿等问题时，不能判定首版合格。

## 13. 与当前仓库的集成约束

以下基于当前工作区的文档与代码检查，用于约束后续方案，不构成现成能力承诺。

- **沿用已有插件机制。** 采用桌面插件 UI 与通用插件后端组合，使用已有面板、插件 API 和事件能力，不把 PPT 专属功能写入核心代理循环。
- **区分桌面插件与后端插件。** 两者的注册、安装和启用是不同环节；应包装成清楚的一套安装与设置体验，缺少后端时界面提供明确状态。
- **复用前先验证。** 仓库已有 PPTX 创建、编辑、模板处理、读取和渲染脚本，可以评估复用；稳定身份、完整样式继承、事务式对话修改与实时工作区仍需新增设计。
- **维护结构化文稿状态。** 后端持有权威文稿与版本；前端负责选择、预览和交互，不能把聊天回复或预览图片当作文稿唯一来源。
- **按文稿与配置作用域隔离。** 文件位置通过宿主提供的作用域路径解析，不硬编码用户主目录，不把某次启动的路径当作所有会话的路径。
- **保持对话缓存稳定。** 文稿变化通过当前指令、对象引用和工具结果传递，不为每次 PPT 编辑重建系统提示词或切换整套工具。
- **能力由会话和可达性决定。** 桌面交互能力不能只依赖后端进程环境变量；远程后端缺少预览或渲染能力时应清楚显示状态。
- **事件更新有回退。** 优先使用宿主支持的事件通道，通道不可用时提供有界刷新机制；不能让无法建立独立 socket 的连接一直不更新。
- **不预选未经验证的底层库。** PPTX 读写、原生母版操作、预览和持久化元数据方案需通过技术验证后确定，并遵守依赖版本上界策略。

## 14. 研发阶段与交付物

| 阶段 | 目标 | 阶段出口 |
| --- | --- | --- |
| M0 技术验证 | 验证可编辑对象、真实母版 / 版式、编号持久化、预览选中映射 | 有真实样例和兼容验证记录，明确支持范围及不可表达的局部例外 |
| M1 创作基础 | 创建文稿、页面管理、编号命名、元素列表、预览、项目保存与 PPTX 导出 | 能生成并重新打开持续编辑的作品，导出对象可编辑 |
| M2 对话编辑 | 精确定位、多对象操作组、母版联动、属性覆盖、撤销与恢复 | 局部与全局修改行为稳定，错误不破坏原稿 |
| M3 主题与完整验收 | 主题预设、对话换风格、质量检查、性能和异常验证 | 五项核心能力全部完成，形成完整首版 |

每个阶段至少产出对应的交互结果、支持矩阵和验证记录。M1、M2 可作为内部里程碑，不能替代完整首版承诺。

最终交付物包括：可安装插件包、内置母版与主题、可编辑示例 PPTX、项目保存与恢复说明、能力及兼容矩阵、用户使用说明、关键行为和真实文件验收记录。

## 15. 后续增强与待评审事项

### 15.1 P1 / P2 候选

| 优先级 | 能力 | 说明 |
| --- | --- | --- |
| P1 | 导入企业 PPTX / POTX 与历史文稿 | 先识别原生对象、母版和可编辑范围，明确不支持内容 |
| P1 | 多母版及母版公共对象的单页变体 | 提供清楚的来源、例外和再次统一机制 |
| P1 | 外部软件编辑后重新导入并匹配编号 | 处理标识被修改、删除、复制以及元数据丢失 |
| P1 | 高级图表、批量素材、参考图和品牌包 | 扩展对象和风格能力，保持原有编辑合同 |
| P1 | PDF 导出、讲稿备注及更多预览方式 | 独立评估真实使用需求 |
| P2 | PowerPoint/WPS 双向实时同步 | 需要独立连接、版本冲突和应用兼容方案 |
| P2 | 多人协作与复杂动画编辑 | 不占用首版完整交付范围 |

### 15.2 开发前需确定

1. 正式插件名与发布渠道，首版选择本地后端还是同时支持远程后端。
2. PowerPoint/WPS 的具体支持版本，以及初始 Windows 环境的验证方式。
3. 首批母版与三类主题的视觉稿、可用字体和素材来源。
4. PPTX 元数据持久化方案及外部软件保存后的保留情况。
5. 母版公共对象的单页例外是否需要提升到首版强制范围；若提升，需先验证原生结构及后续联动方案。
6. 结合实测调整容量和性能基线，再评估排期与人力。

目前已确认的产品边界是：**用户在 forx 插件里边聊边预览、持续修改同一份作品，并导出可继续编辑的 PPTX。** 其余待评审事项不会改变五项核心目标，但会影响兼容范围和实现成本。
